# Что запрашивать у школы для теста ЛАД

Операционный документ: с чем идти к завучу. Поля выверены по модели данных
(`src/lad/model.py`, `src/lad/tables.py`) — это ровно то, что система читает
на входе, без лишнего.

Позиционирование и каналы — `POSITIONING.md`.

---

## Главный принцип: не просить заполнять формы

Завуч не будет заполнять наши таблицы. У него нет на это времени, и просьба
сама по себе выглядит как работа, которую мы перекладываем на него.

**Просим то, что у школы УЖЕ существует в готовом виде**, и разбираем сами:

| Что просим | Что это закрывает | Есть ли у школы готовым |
|---|---|---|
| **Тарификация на учебный год** | нагрузку целиком: класс + предмет + учитель + часы | ✅ обязательный документ, есть всегда |
| Действующее расписание | «было» для сравнения, деления на подгруппы, смены | ✅ висит на сайте или в журнале |
| Список кабинетов | спецкабинеты, вместимость | ✅ есть у завхоза |
| Список классов с числом учеников | размеры групп | ✅ есть в отчётности |

**Тарификация — 80% всего.** Если дадут только её, тест уже возможен.
Всё остальное достраивается или подставляется по умолчанию.

---

## Уровень 1 — минимум, без которого не запустится

### 1.1. Нагрузка (тарификация) — ГЛАВНАЯ ТАБЛИЦА

Одна строка = один предмет в одном классе у одного учителя.

| Поле | Обяз. | Пример | Комментарий |
|---|---|---|---|
| класс | ✅ | 7Б | |
| предмет | ✅ | Физика | |
| учитель (ФИО) | ✅ | Иванова И.И. | |
| часов в неделю | ✅ | 2 | дробные (0,5) — отдельной строкой по чётности |
| подгруппа | — | 1 / 2 / юноши / девушки | пусто = весь класс. **Критично: без этого модель ломается** |
| уровень | — | базовый / повышенный | влияет на предельную нагрузку |
| тип | — | урок / факультатив | |
| кабинет | — | 204 | если предмет закреплён за кабинетом |

### 1.2. Классы

| Поле | Обяз. | Пример |
|---|---|---|
| класс | ✅ | 7Б |
| учеников | ✅ | 24 |
| смена | — | 1 / 2 |
| повышенный уровень | — | да / нет |
| язык обучения | — | русский / белорусский |
| профиль (X–XI) | — | физмат |

### 1.3. Режим школы (три вопроса устно)

- Пятидневка или шестидневка?
- Максимум уроков в день (обычно 8)?
- Есть ли вторая смена и у каких параллелей?

## Уровень 2 — для результата, который не стыдно показать

### 2.1. Учителя

| Поле | Зачем |
|---|---|
| ФИО | ключ связи с нагрузкой |
| **методический день** | день, когда учителя нет в школе. Без него расписание нереалистично |
| **совместитель** (да/нет) | работает в двух школах — физически не свободен |
| свой кабинет | кабинетная система |
| максимум уроков в день | потолок нагрузки |
| **недоступные слоты** | «по вторникам не может», «первым уроком не ставить» |

Недоступные слоты — то самое, что живёт в голове завуча и нигде не записано.
Спрашивать голосом, списком: «кого и когда нельзя ставить».

### 2.2. Кабинеты

| Поле | Пример |
|---|---|
| номер | 204 |
| тип | обычный / физика / химия / биология / спортзал / компьютерный / мастерская |
| мест | 30 |
| корпус | 1 / 2 — переход между зданиями требует времени |
| классов одновременно | для спортзала бывает 2 |

### 2.3. Предметы

Обычно достраивается автоматически из типового учебного плана № 75.
Уточнять только нестандартное:

- предмет требует спецкабинета и **только его**;
- предмет всегда ставится парой (сдвоенный урок).

## Уровень 3 — для честного сравнения «было / стало»

**Действующее расписание школы** в любом виде: выгрузка, Excel, PDF, фото доски.

Без него нет колонки «было», а значит нет главной цифры демо. Из него же
восстанавливаются деления на подгруппы, которых в тарификации может не быть
видно.

⚠️ Метрики «было» и «стало» считает один и тот же валидатор
(§8.3 CLAUDE.md). Иначе сравнение — враньё, и завуч вскроет его первым вопросом.

---

## Чего НЕ просить

- ❌ Персональные данные учеников — не нужны вообще. Система работает
  с классами и группами, а не с фамилиями детей. **Говорить это первым:**
  снимает главное возражение про защиту данных.
- ❌ Оценки, журналы, посещаемость — не наш модуль.
- ❌ Заполнить нашу форму с нуля.
- ❌ Доступ в их системы.

---

## Про персональные данные — проговаривать самим

ФИО учителей — единственные персданные на входе, и они нужны только чтобы
завуч узнал своих в готовом расписании.

Что говорить:
1. Солвер умеет работать **на обезличенных данных** («Учитель 1», «Учитель 2») —
   флаг анонимизации есть.
2. Для показа третьим лицам, блога и видео — **только обезличенный вариант**
   (§8.4 CLAUDE.md).
3. Данные учеников не запрашиваются ни в каком виде.

Учитывая, что частные платформы убрали с рынка именно за персданные
(см. `POSITIONING.md`, «Регуляторный контур»), этот пункт озвучивается
до того, как его задаст собеседник.

## Формулировка запроса

Коротко, без питча, с понятным объёмом работы для школы:

> Делаю систему автоматического составления расписания под белорусские
> санитарные нормы. Хочу проверить её на реальных данных.
>
> Нужна тарификация на этот год — в том виде, в каком она у вас есть,
> хоть Excel, хоть скан. Если можно, ещё действующее расписание и список
> кабинетов.
>
> Данные учеников не нужны. ФИО учителей нужны только чтобы вы узнали
> своих в результате — для любого показа наружу они обезличиваются.
>
> Взамен пришлю готовое расписание вашей школы и разбор, где у нынешнего
> нарушены нормы. Ни к чему не обязывает.

Последний абзац — самое важное. Это не просьба об услуге, а обмен:
школа отдаёт то, что у неё и так лежит, и получает работающий результат.
