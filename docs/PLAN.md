# План: продукт ЛАД за 5 дней (14.09 → 19.09.2026)

## Почему план поменялся

13–14.09 через амбассадора Startup Space о проекте рассказали министру:
«ребята поддержат, делай продукт». Это та ветка точки выхода §10 CLAUDE.md
(«есть интерес → строим продукт из §5»), и запреты §6 («без UI, без БД,
без деплоя») больше не действуют. Действует новый таймбокс: **пять дней**.

Что нужно показать через пять дней — не демо, а продукт, который завуч может
открыть и сам, без нас, пройти путь:

> загрузил нагрузку → получил расписание → поправил руками, и система на ходу
> объясняет, почему сюда нельзя → забрал в Excel или распечатал → в понедельник
> учитель заболел, и система предложила замены.

## Что уже есть и остаётся

Ядро на Python — `src/lad/`: солвер CP-SAT, санитарные нормы РБ по
первоисточникам, валидатор, разбор причин, если расписание не складывается,
выгрузка в Excel и HTML. **Ядро не переписываем**, продукт строится поверх него.

Streamlit (`app.py`) живёт до 19.09 как запасной вариант для показа и затем
выключается.

## Архитектура

```
web/     React + Vite + TypeScript + Tailwind — интерфейс
server/  FastAPI — HTTP-обёртка над src/lad, SQLite, фоновые задачи солвера
src/lad/ ядро (без изменений в интерфейсе функций)
```

- **Школа** хранится одним JSON-документом в SQLite (тот же формат, что сейчас
  `data/school.json`), расписания — версиями. Миграции схемы не нужны.
- **Солвер** работает в отдельном процессе: прогресс идёт в браузер через SSE,
  «стоп» гарантированно останавливает поиск, и падение солвера не роняет сервер.
- **Правка вручную** проверяется на сервере тем же `lad.validate`, что считает
  итоговые цифры, поэтому то, что показывает сетка, совпадает с отчётом.
- **Деплой**: Railway, один сервис (FastAPI отдаёт собранный фронт).
  Нужно минимум 4 vCPU — меньше солвер не тянет (`available_cpus` в solve.py).
